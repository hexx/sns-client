# リッチ本文はプロバイダ固有のまま越境させず、BFF で「統一インラインリッチテキスト」に変換して Post に載せる

Misskey の MFM＋カスタム絵文字（misskey.io は絵文字・装飾が多い）を、プレーンテキストへの縮退でも UI 側のプロバイダ別レンダラでもなく、**プロバイダ非依存の小さなインラインリッチテキストスキーマ**（`text` / `link` / `mention` / `hashtag` / `emoji` のセグメント列）に変換して `Post` に載せる。変換は BFF 側で行い（Misskey は `parseMfm` を使用）、UI はその1スキーマだけを描画する。カスタム絵文字は URL 付き `emoji` セグメント（inline 画像）として1次対応に含める。

既存の設計が「本文はプレーンテキスト＋リッチなものは Media / LinkCard として構造化して越境させる」方針だったのを、本文のインライン要素にも同じ思想を拡張する。`$[spin ...]` 等の凝った MFM 効果はまずプレーンテキストへ縮退し、対応は上記サブセットから始める。

プレーンテキスト縮退は misskey.io の表現力（カスタム絵文字・装飾）をほぼ損なうため却下。UI 側のプロバイダ別レンダラ（mfm-js 等をバンドル）は手っ取り早いが Misskey 固有実装が UI に漏れ、かつ Bluesky facets には効かないため却下。統一スキーマは「UI は Post だけを扱う」原則を保ったまま再現性が得られ、将来 Bluesky facets を同じスキーマに載せてリンク/メンションを描画する拡張にも効く。

## Considered Options

- プレーンテキストに縮退（MFM・カスタム絵文字を除去）— 却下：misskey.io の体验が著しく劣化
- Post にプロバイダ固有ボディを載せ UI がプロバイダ別レンダラで描画 — 却下：UI に Misskey 固有実装が漏れる・Bluesky facets に再利用できない
- **BFF で統一インラインリッチテキストに変換して Post に載せる（採用）**

## Consequences

- Worker に Misskey 固有のパース処理（@misskey-dev/misskey-js の `parseMfm` 等）と、スキーマへの変換ロジックが追加される。
- UI の本文描画が `<p>{text}</p>` から、スキーマを描画するレンダラに置き換わる。
- 未対応の MFM 効果はプレーンテキストに縮退するため、表現の一部は意図的に失われる（段階的に対応範囲を拡大）。
- 将来 Bluesky facets も同一スキーマに変換すれば、リンク/メンションのクリック対応が Misskey と共通の描画で実現できる。
