# スマホ UI は全ページ常時マウントのスワイプページング

スマホ（<1024px）の UI を、複数 View の横スワイプ・ページングで再定義し、**全ページを常時マウント**して全 View のポーリングを継続する（[mobile-paging-spec.md](../mobile-paging-spec.md)）。デスクトップのデッキが持つ「複数 View の常時監視」の価値をスマホにも載せるため、軽量化（遅延マウント・アクティブのみポーリング）より監視性とスクロール位置保持を優先した。

## Considered Options

- **ボトムタブバー（View をタブ化、上限5程度）**: 到達性は良いが、デッキの「N個の View」の自由度が5個で頭打ちになり、タブに出す View の選別問題が新たに生まれるため不採用。
- **アクティブページのみマウント（遅延マウント）**: 軽い。しかし View 切替でスクロールが先頭に戻り、非表示 View のポーリングが止まるため、本決定の問題定義（監視性の欠如）が再発する。
- **全マウントだがポーリングはアクティブ ± 隣接のみ**: 中間案。「見ていない View の新着がわからない」半端さが残るため不採用。

## Consequences

- スマホでも全 Source のポーリングが裏で常時走る。単一ユーザー・数 View 前提（deck-view-spec §「数カラム前提」）ではデスクトップのデッキと同等の負荷であり許容する。View 数が大きく増える場合は再考の余地がある。
- 非アクティブ View の新着通知はタブストリップのバッジが受け皿になる（ページ内ピルとの二層構造）。
