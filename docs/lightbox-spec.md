# Lightbox（投稿画像の拡大表示）仕様

> 複数 SNS を1画面で扱う PWA クライアント（[sns-client-spec.md](./sns-client-spec.md)）に、
> **投稿の添付画像を選択したとき、拡大表示する**拡張の確定仕様。デッキ UI・スマホ UI の両方に適用する。
> 作成: grill-with-docs セッション（全9問合意）に基づく。
> 関連仕様: [linkcard-display-spec.md](./linkcard-display-spec.md)（LinkCard サムネイルは対象外）、[misskey-reaction-action-spec.md](./misskey-reaction-action-spec.md)（同じ PostCard 上の操作拡張）。用語は [CONTEXT.md](../CONTEXT.md) 参照。

---

## 1. 背景・目的

- 現状の MediaGrid（`app/src/components/PostCard.tsx`）は `<img>` を並べるだけで、**クリックしても何も起きない**。fullsize 画像を見る手段がなかった。
- 起点の要望: 「投稿の画像を選択したら拡大表示してほしい」。
- BFF は既に fullsize 優先でマッピングしている（`worker/src/bsky.ts` extractMedia: `fullsize || thumb`）ため、`Media.url` をそのまま拡大表示に使える。モデル変更は不要。

## 2. スコープ

### 今回（確定）

- 投稿に添付された画像（MediaGrid の `Media`）の拡大表示。1投稿内の複数画像を切り替えられるギャラリー型。
- alt の常時表示、読み込み中・失敗時の状態表示、最低限のアクセシビリティ（ダイアログ意味付け・フォーカス管理・スクロールロック）。

### 非目標（今回は対象外）

- 引用カード（QuoteCard）のサムネイル・LinkCard のサムネイル・アバターの拡大（別系統の要素）。
- ズーム・パン（ピンチ操作）。画像は画面に収まる最大サイズで固定。
- 下スワイプによるドラッグクローズ。
- CW との連携（PostCard の CW 表示自体が未実装。`contentWarning` フィールドは `shared/types.ts` に存在するが描画されていない）。
- 動画メディア（`Media.type` は `'image'` のみ）。
- Compose モーダルへのアクセシビリティ遡及適用（本仕様の基準を既存モーダルには広げない）。

## 3. 用語（`CONTEXT.md` 反映済み）

- **Lightbox（ライトボックス）**: 投稿に添付された Media を拡大して見せる重ね合わせ表示。投稿内の画像を選択すると開き、背景を暗くして、画面に収まる最大サイズで1枚ずつ表示し、同じ投稿内の複数画像を切り替えられる。識別子・正式名が Lightbox で、日本語の「拡大表示」は説明語。
  _Avoid_: MediaViewer, ImageViewer, gallery, modal

## 4. ドメインモデル（`shared/types.ts`）

**変更なし。** 既存の `Media = { type: 'image'; url: string; alt?: string }` のみで足りる。

- `Media.url` は BFF が fullsize 優先でマッピング済み → Lightbox は `url` をそのまま読み込む。拡大表示専用の別 URL フィールドは追加しない。
- 1投稿あたりの画像は最大4枚（MediaGrid が `slice(0, 4)`）。Lightbox も同じリストを同じ順序で表示する。

## 5. トリガーと開閉

### 5.1 開く

- MediaGrid の各サムネイルを `<button>` 化し（現状は裸の `<img>`）、クリックで Lightbox を開く。キーボード操作可能であること（フォーカス可能、Enter/Space で開く）。
- **開く位置**: クリックした画像を1枚目（インデックス = 投稿内での位置）として開く。
- サムネイル上は `cursor: zoom-in`（操作可能の視覚的手がかり）。
- Lightbox は投稿単位。表示できるのは同じ投稿の Media のみ（複数投稿をまたぐギャラリーにはしない）。

### 5.2 閉じる

以下のいずれかで閉じる:

1. 背景（画像・コントロール以外の領域）のタップ
2. × ボタン
3. Esc キー
4. 画像本体のタップ

- 下スワイプのドラッグクローズは採用しない（実装コストの割に偶発的な閉じやすさが懸念されるため）。
- 閉じたら開き元のサムネイルへフォーカスを返す（§8.2）。

## 6. 表示

### 6.1 全体構成

- 全画面オーバーレイ: `position: fixed; inset: 0`、暗い背景（`rgba(0, 0, 0, 0.9)` 程度）、`z-index` は既存モーダル（`.modal-backdrop` = 30）より上の 40。
- 画像は `object-fit: contain` で画面に収まる最大サイズ。ズームなし。
- 縦の並び: 画像領域（可変）→ alt（内容に応じた高さ）。

### 6.2 ギャラリー

- 同じ投稿内の複数画像を ←/→ ボタン・スワイプ・キーボード ←/→ で切り替える。
- **位置表示**: 左上に「2 / 4」形式（現在位置 / 総枚数）。
- **端の扱い**: 先頭では ← を無効、末尾では → を無効（循環しない）。端でのスワイプは何もしない。
- **画像1枚の投稿**: ←/→ ボタンと位置表示は非表示。スワイプは何もしない。

### 6.3 コントロール配置

| 要素 | 位置 |
|---|---|
| × ボタン | 右上 |
| 位置表示「2 / 4」 | 左上 |
| ← / → ボタン | 画面左右の中央 |
| alt | 画像の下に全幅 |

### 6.4 alt

- 拡大ビューの画像下に**常時表示**する。
- alt がなければ何も表示せず、**空領域も確保しない**。
- 長い alt は切り詰めず全文を表示する（アクセシビリティ情報なので省略しない）。alt が長い場合は画像領域がその分だけ縮んで収まる。

## 7. 読み込みと失敗

- **読み込み中**: 暗い背景の中央に控えめなスピナーを表示する。スケルトンやプレースホルダー枠は出さない。
- 画像ごとに独立した読み込み状態を持つ。スピナーは今表示している1枚にのみ出す。
- **先読み**: 隣（インデックス ±1）の画像は先読みし、切り替えがほぼ瞬時に終わるようにする。
- **失敗時**: 中央に「画像を読み込めませんでした」を表示し、alt があればその下に alt も表示する。「再試行」ボタンを1つ置き、タップで当該画像の読み込みをやり直す。

## 8. アクセシビリティ

### 8.1 ダイアログ意味付け

- Lightbox のルートに `role="dialog"` + `aria-modal="true"` + `aria-label="画像の拡大表示"`。
- ボタンの `aria-label`: × は「閉じる」、← は「前の画像」、→ は「次の画像」。
- `<img>` の alt 属性は維持する（可視の alt テキストとは別に、画像要素自体にも alt を付ける）。

### 8.2 フォーカス管理

- 開いた瞬間に × ボタンへフォーカスを移動する。
- Tab は Lightbox 内（×・←・→）で循環する（フォーカストラップ）。背景のタイムラインへは抜けない。
- 閉じたら、開き元にしたサムネイルのボタンへフォーカスを返す。

### 8.3 背景スクロールロック

- 表示中は body のスクロールを止める（背後でタイムラインが動かないようにする）。閉じたら元に戻す。

### 8.4 キーボード

- Esc: 閉じる。←/→: 画像切り替え（端では無効、1枚のときは無効）。
- サムネイルはボタンなので、Tab でフォーカスして Enter/Space で開ける。

## 9. アニメーション

- **開閉**: 背景フェード（150ms 程度）と画像のフェードインのみ。サムネイルから実寸へ広がるズーム遷移は採用しない（実装コストの割に効果が小さい）。
- **切り替え**: 即時差し替え（スライドアニメーションなし）。
- `prefers-reduced-motion` が有効な場合はすべて即時表示。

## 10. エッジケース

1. **画像1枚の投稿**: ←/→・位置表示なし。閉じる操作のみ有効。
2. **端での操作**: 先頭での ←（と左スワイプ）、末尾での →（と右スワイプ）は何もしない。循環しない。
3. **切り替え中に前画像が未ロード**: スピナーは表示中の画像にのみ付く。先読みが完了していれば切り替えは瞬時に終わる。
4. **失敗後に再試行して成功**: 通常表示に移行する。失敗状態は画像ごとに独立しているので、他の画像の表示に影響しない。
5. **alt が非常に長い**: 画像領域が縮んで alt 全文が表示される。切り詰め・クランプはしない。
6. **スワイプの判定**: 水平方向に 50px 以上、かつ水平成分が垂直成分より大きい移動をスワイプとする。縦方向の移動は何もしない（ドラッグクローズ不採用のため）。
7. **画像タップとコントロールの衝突**: ←/→・× は画像と重ならない独立要素として描画し、タップはそれぞれ自身の動作のみ行う（画像タップによる閉じと干渉しない）。
8. **同時複数表示**: Lightbox は開くと全画面を覆うため、2つ同時に開くことは UI 上起きない。投稿ごとに独立した状態を持つが、排他制御は不要。
9. **画面回転・リサイズ**: `object-fit: contain` が追従するため追加対応は不要。

## 11. テスト（ADR-0001 / ADR-0002 準拠）

`app/src/components/PostCard.test.tsx`（既存の PostCard コンポーネントテストを拡張。Lightbox は PostCard 配下の実装とする）:

- サムネイルクリックで Lightbox が開く（`role="dialog"`・`aria-modal`・`aria-label="画像の拡大表示"` の存在）
- 2枚目クリックで開くと位置表示が「2 / 4」
- → / ← ボタンで画像が切り替わり位置表示が更新される。端では無効（循環しない）
- 画像1枚の投稿では ←/→ ボタンと位置表示が描画されない
- alt が画像下に表示される。alt なしでは alt 要素自体がない
- × ボタン・Esc・背景クリック・画像クリックのそれぞれで閉じる
- 開いたとき × にフォーカスがある。閉じたら開き元サムネイルにフォーカスが戻る
- 表示中は body のスクロールがロックされ、閉じると解除される
- 読み込み失敗時にエラーメッセージと「再試行」ボタンが出る

BFF・モデル変更はないため、worker 側テストの変更はなし。
