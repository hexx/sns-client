# 新着境界仕様（取り込み後の未読範囲の可視化）

> 複数 SNS を1画面で扱う PWA クライアント（[sns-client-spec.md](./sns-client-spec.md)）に、
> **新着の取り込み後「どこからが未読か」を視覚的に示す**拡張の確定仕様。デッキ UI・スマホ UI の両方に適用する。
> 作成: grill-with-docs セッション（全8問合意）に基づく。
> 関連仕様: [mobile-paging-spec.md](./mobile-paging-spec.md)（§4.3・§4.4 を本仕様が改定）、[deck-view-spec.md](./deck-view-spec.md)（更新モデル不変）。用語は [CONTEXT.md](../CONTEXT.md) 参照。

---

## 1. 背景・目的

- 既存の新着通知は「未取り込み（pending）を自動挿入せず、ピル（「新着 N 件」）とスマホのタブバッジで知らせる」モデル。**取り込み（ピルタップ）は新着を先頭に挿入してスクロールするだけで、新着と既存投稿の視覚的区別が一切なかった**。
- このため「新着を取り込んだのはいいが、**どこから読んでないのかが分からない**」という問題があった。複数 Source を時系列マージする本アプリでは、新着が必ずしも先頭のかたまりになるとも限らない（§3.2）。
- またスマホでは、タブバッジのタップは「バッジ消去＋ページ切替」のみで、取り込みにはページ内ピルの別途タップが必要だった（二段階操作）。
- 本仕様は**未読**の概念を導入し、取り込み時に**区切り線**と**投稿単位の強調**を表示することで、「どこから読んでないか」の曖昧さを解消する。

## 2. スコープ

### 今回（確定）
- **未読**の概念: 新着の取り込みでリストに挿入された投稿のうち、利用者がまだ到達していないもの。セッション内のみで保持（リロードで消える）。
- **区切り線**: 最古の未読投稿の直下に表示。文言は「新着はここまで」。
- **未読強調**: 未読投稿ごとの薄い背景色。
- **既読クリア**: 区切り線が画面に表示された瞬間に全未読をクリア（フェードアウト）。
- **タブタップでの自動取り込み**（スマホ）: 未取り込み新着のあるタブのタップで、取り込み＋先頭スクロールまで行う（mobile-paging-spec §4.3・§4.4 の改定）。
- デッキ・スマホ**両方**に適用（`TimelineCore` 共通実体への実装）。

### 非目標（今回は対象外）
- 既読状態の**永続化**（リロードをまたぐ保持・複数デバイス同期）。BFF/KV への保存はしない。
- 新着のシステム通知・トースト等の追加通知。
- ピルの文言・タップ挙動自体の変更（取り込み後に区切り線が付くようになるだけ）。
- ポーリング間隔・自動挿入しない方針など、更新モデル自体の変更。

## 3. 未読の定義

### 3.1 何が未読になるか

単一ルール: **「利用者の見ていないうちにリストへ挿入された投稿」＝未読**。経路ごとの適用:

| 挿入経路 | 未読マーク |
|---|---|
| ピルタップによる取り込み（`applyPending`） | **○** |
| スマホのタブタップによる自動取り込み（§4.2） | **○** |
| 手動更新 / pull-to-refresh（`refresh`） | **○** |
| 追加読み込み（無限スクロール。過去へ遡る古い投稿） | × |
| 投稿直後の自分の投稿（`justPosted`。別経路で挿入時に既知扱い） | × |
| 初期ロード | × |

### 3.2 区切り線の位置（複数 Source マージの帰結）

- 区切り線は、マージ済みリスト（`createdAt` 降順）において**最古の未読投稿の直下**に置く。未読はすべて区切り線の上にある。
- `TimelineCore` は複数 Source を `createdAt` 順に合成するため、**未読が既読の間に混ざることがある**。例: Bluesky の 10:00 の投稿は取り込み済み（既読・表示中）だが、Misskey の **9:58** の投稿がポーリングのタイミング差で後に pending 入りした場合、取り込み後にこの新着は既読投稿の**下側**に挿入される。
- ゆえに**投稿単位の強調が未読表現の本体**であり、区切り線は「ここまで来たら全部読んだ」を示す境界の目印である。区切り線は「上にあるのが全部未読である」ことを主張しない（主張できない）。

### 3.3 追加取り込み

- 未読が残っている間にさらに新着が取り込まれた場合（ピルの再表示→タップ、手動更新）、新しい投稿は**既存の未読セットに合流**する。
- 区切り線は**最古の未読の位置に留まる**（より下へは移動しない）。

### 3.4 既読クリア

- スクロールにより**区切り線が可視領域に入った瞬間**、全未読をクリアする（区切り線と強調の背景色をフェードアウトで消去）。
- 取り込み直後に区切り線が**既に可視領域内**にある場合（新着が少数で、ユーザーが先頭にいる等）は、その場でほぼ即座に既読クリアされる。唐突さはフェードアウトで緩和する。
- ページ切替（スマホのスワイプ）や非表示ではクリア**されない**。区切り線が表示されるまで未読は維持される（全ページ常時マウントにより状態は保持される。mobile-paging-spec §4.2）。
- リロードで全状態が消える（セッション内のみ）。

## 4. トリガー別の挙動

### 4.1 ピルタップ（デッキ・スマホ共通。既存の拡張）

- 挙動は不変: pending を各 Source の先頭に挿入し、先頭へスムーススクロール。
- 追加: 挿入された投稿を未読マークする（区切り線＋強調が現れる）。

### 4.2 スマホのタブタップ（新規）

- タップした View に pending がある場合: **自動取り込み＋先頭スクロール＋未読マーク**（ピルタップと同等の結果）。
- pending がない場合: 通常のページジャンプ（挙動不変）。
- **スワイプは対象外**: スワイプはカジュアルな移動であり、mobile-paging-spec §4.2 が価値として置く「スクロール位置の保存・復元」を壊さないため。pending を抱えたページへスワイプした場合は、ページ内のピルが引き続きシグナルを担う（ピルタップで同じ結果が得られる）。

### 4.3 手動更新 / pull-to-refresh（デッキ・スマホ共通。既存の拡張）

- 新しく取得した投稿を先頭に挿入（不変）＋未読マーク。
- 手動更新時ユーザーは先頭にいるため区切り線は通常すでに可視領域内 → 実態は「新着分が一瞬強調されて消える」短いフィードバック演出になる。

### 4.4 スマホの新着通知（改定。mobile-paging-spec §4.4 を置き換える）

| 状態 | 通知手段 |
|---|---|
| アクティブページの未取り込み新着 | ピル「新着 N 件」（タップで取り込み） |
| 非アクティブページの未取り込み新着 | タブバッジ（件数。**タップで自動取り込み＋ジャンプ**） |
| 取り込み済み・未読 | 区切り線「新着はここまで」＋投稿の強調（スクロールで消える） |

- バッジの件数ソースは不変（View ごとの pending 数）。タブタップで自動取り込みされるため pending は 0 になり、バッジは結果として消える。
- スワイプによるアクティブ化では、バッジは消えるが取り込みは行われない（ピルが引き継ぐ）。

## 5. ビジュアル

- **区切り線**: アクセントカラー系の細線＋文言**「新着はここまで」**。投稿と投稿の間に全幅で挿入される。
- **未読強調**: 未読投稿にアクセントカラー系の**薄い背景色**。
- **意味の配分**: 区切り線の文言が一次情報、背景色は補助。**色だけに意味を載せない**（色覚多様性への配慮）。
- **フェードアウト**: 既読クリア時、区切り線と背景色はフェードして消える（突然消えない）。
- 色味・濃度・アニメーション時間の具体的な数値は実装時に調整する。

## 6. エッジケース

1. **未読が既読の間に混ざる**（§3.2）: 区切り線は最古の未読の直下に留まり、散在する未読は強調が示す。
2. **未読残り中の追加取り込み**（§3.3）: 合流。区切り線は下へ移動しない。
3. **取り込み直後に区切り線が既に可視**（§3.4）: 即時既読クリア＋フェード。
4. **未読を残してページを離れ、スワイプで戻る**: 再取り込みは起きず（pending なし）、スクロール位置は復元され、未読と区切り線は維持される。
5. **未読を残してリロード**: 全クリア。タイムラインは再取得され、先頭から全既読状態で始まる。
6. **投稿直後**: `justPosted` は別経路で挿入時に既知扱いされるため、自分の投稿が未読マークされることはない。
7. **追加読み込み**: 過去へ遡って取得した古い投稿は未読にならない（「見ていないうちに挿入」は新着の発見のみを指す）。
